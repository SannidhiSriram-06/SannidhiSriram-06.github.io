01 AWS, us-east-1 · Terraform

Identity Threat Detection and Response Lab

One t3.large on AWS running HashiCorp Vault and a single-node Wazuh SIEM, built with Terraform. Vault issues short-lived IAM users on request. Wazuh reads the host's auth log and AWS CloudTrail and raises alerts that I mapped to MITRE ATT&CK.

Terraform, HashiCorp Vault, Wazuh, AWS CloudTrail, Docker Compose

What works. 33 alerts from 5 custom rules: SSH username spraying (T1110), sudo abuse (T1548.003) and IAM user creation (T1078.004, T1098). A Vault-issued IAM user was deleted when its 900 second lease expired and when I revoked it.

Limits. I ran the attacks from localhost on the same host. The incident-response runbook is written but I did not run it against the live alerts. Wazuh uses default credentials, so this is lab-only.

  1. 02 AWS · Terraform

    Cloud Compliance and Vendor Risk Lab

    Terraform deploys deliberately misconfigured resources: a public S3 bucket, an open SSH security group, an unencrypted EBS volume and an IAM user without MFA. AWS Config and Security Hub check them against the CIS AWS Foundations Benchmark v1.4.0. EventBridge sends failures to a Lambda that writes a risk register to S3.

    What works. 21 findings recorded, 17 mapped to CIS controls and 4 unmapped, each with an owner and an SLA. A command-line script scores a fictional vendor from a sample questionnaire, and a small Flask dashboard shows the register and the score.

    Limits. The ISO 27001 and NIST CSF mappings are my own indicative crosswalk, not an official one. The vendor and its answers are made up.

    Terraform, AWS Config, Security Hub, Lambda (Python), Flask

  2. 03 AWS, us-east-1 · Terraform

    Cloud Support Simulation

    Two support tickets against a Flask app on one EC2 instance, worked the way a support engineer would: over an AWS Client VPN endpoint with mutual-TLS certificates and SSM Session Manager, with logs in CloudWatch Logs Insights.

    What works. Ticket 1: a missing security group rule, found from the logs and fixed. Ticket 2: deleted data restored from an AWS Backup recovery point. The restore reported COMPLETED, but a file written seconds before the backup was missing, so I checked the restored instance before telling the customer. The write-ups are two incident reports, two knowledge-base articles and customer updates.

    Limits. One instance in the default VPC with a public IP. SSM session logging is not configured.

    Terraform, AWS Client VPN, SSM Session Manager, AWS Backup, CloudWatch

  5. 06 AWS, us-east-1 · Terraform

    Self-Healing Java Microservice

    A Spring Boot service in Docker on an Auto Scaling Group (2 to 4 t3.micro across two Availability Zones) behind an Application Load Balancer, all in Terraform. The recovery layers are an Actuator health endpoint, a Docker health check, ALB health checks, ASG instance replacement and CPU target tracking at 80%.

    What works. The ALB marks a target unhealthy after 3 failed 30 second checks (about 90 seconds) and the ASG replaces it. GitHub Actions builds, tests, pushes to Docker Hub and runs Snyk scans; it ran green in February 2026.

    Limits. Snyk runs after the image is pushed, so a finding fails the run but does not stop publishing. Deploying the new image to EC2 is manual. CI now fails at the Docker Hub login because the secrets are no longer set.

    Terraform, ALB and ASG, Spring Boot, GitHub Actions, Snyk

  6. 07 AWS, us-east-1 · Serverless

    Bookstore Serverless API

    A Node.js 20 Lambda behind an API Gateway REST API serving GET and POST /books, with CloudWatch Logs. I built it to map a bookstore API onto serverless services.

    What works. It costs $0 a month while idle on the Free Tier. The AWS resources were deleted after testing.

    Limits. The handler keeps books in an in-memory array. A MongoDB Atlas cluster was set up but never connected, so a POSTed book does not persist.

Experience

AI Intern and Cloud Deployment Lead, Infosys Springboard

Remote · February to April 2026 · AI KYC verification system

A 25-member team split into ML, web and cloud sub-teams. I led the cloud sub-team and was one of two co-leads, alongside the ML lead, coordinating all three.

In sprint 14 I took the system to AWS: the React frontend on S3 static hosting, and the Node.js API and the Flask ML service (three GNN document models) on EC2, both run under PM2. Five deployment defects came up:

Request path
The frontend called the ML service directly, bypassing the backend and breaking auth and CORS. I routed everything through one backend endpoint.
Bind address
The Node.js API listened on 127.0.0.1 only and refused outside connections. I bound it to 0.0.0.0.
CORS
The API only allowed localhost:5173, which blocked the S3-hosted frontend. I added the S3 origin.
PM2 interpreter
PM2 started the ML service with system Python, which crashed on a missing numpy. I pointed PM2 at the virtual environment's interpreter.
Bad uploads
A random non-KYC image could crash the flow. I added a "Non-KYC Document" result path end to end.
